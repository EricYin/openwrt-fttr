# 现场实验与分层验证

## 实验合同

每次实验写清：目标别名、当前注册、假设、区分证据、单一变量、基线、操作、时限、成功条件、失败条件、恢复动作和恢复证据。
临时文件、探针、配置更改及进程操作先登记再执行。停止任务前逐项清理；已成为用户保留源码的文件不能按“临时”擅自删除。

配置写入、服务重启、网络路径变更和重置各有独立影响。继承用户已有授权，不反复询问相同操作；也不把一次授权泛化成可清空所有业务。

## 控制实验混杂

- 使用当前完整身份核对 ONU ID，写入前再次核对。状态变化或重注册后重新建立基线。
- 读明锁和租约：合作锁不证明硬件状态已恢复；通道租约与 OMCC 租约不是同一件事，Drop 也可能改变 ONU 侧端口状态。
- 停止 fttrd 可能同时停止周期授权/测距工作；重启可能执行去激活清理并改变所有 ONU。不可把这种前后差异归因于唯一一个 OMCI 属性。
- 不同端点实例排序会改变桥/EVTO 实例映射；新增发现能力须核对已有资源，避免让重试转为冲突。
- 在发出 SET 前准备恢复路径；响应丢失时按“可能已生效”处理。复核写后与恢复后的真实状态。panic、信号、SSH 断开或掉电不能依赖普通函数尾部保证恢复。
- 计时等待必须服务于明确采样窗口或状态退出条件；避免无意义睡眠与无限重试。
- 报文按方向、来源身份、外层 PCP/GEM、内层 VLAN、时间和协议分别统计。内部标签可描述收包映射，不能独立证明物理 ONU 来源。
- 对比基线、候选、恢复阶段时保持授权循环、租约、刺激流量和观察窗口一致。单次出现或静默都是有限证据；未复现则保持“不确定”。

## 验收矩阵

| 层 | 可接受证据 | 不能替代它的证据 |
| --- | --- | --- |
| 注册 | 当前身份、注册代次、O5 确认 | 缓存身份或光功率显示 |
| OMCI | 具体类/实例/属性的请求与回读 | CREATE/SET 已发出、无错误 UI |
| GEM 接收 | 当前窗口内可归属目标的新鲜入站业务报文 | 累计计数、其他 ONU MAC、OMCI 包 |
| GEM 发送 | 目标端接收或可归属目标的响应 | 本机发包计数、抓到自身发包 |
| 宿主门控 | carrier 实际状态、内核是否丢弃下行（`tx_dropped` 与 `fttr0` 是否出现对应 VLAN） | OMCI 回读成功、端口存在 |
| 接线/环路 | 无 `own address as source address`、目标端口包速正常、断开冗余链路后现象消失 | "看起来通了"、单次 DHCP 成功 |
| 原生业务网络 | 真实租约所在接口、桥成员、默认路由、ARP 和定向响应 | 临时别名/host route 成功、页面 Connected |
| 接入终端 | 子猫 LAN/Wi-Fi 终端的实际 DHCP、DNS 和网页访问，注明测试者 | 子猫本机 wget 或 ping 成功 |
| 管理网络 | 目标 DHCP/IP/路由与请求响应 | 主猫已有管理桥或其他 ONU 邻居 |
| CWMP | 目标真实 Inform，以及所验功能的真实 RPC 响应 | OMCI ACS 回读、ACS 监听端口、其他设备会话 |
| 持续性 | 可控重试、重连、运行窗口及其他 ONU 基线对比 | 单次成功、单元测试、编译成功 |

对每层填写已验证/失败/未验证/受阻及证据。任务可完成于明确的调查结论，不要求把所有层涂为成功。

## 先门控、后协议

遇到"OMCI 配置成功但不通"时按固定顺序取证，避免把宿主问题当成 OMCI 问题：

1. 结果码与成对报文（做法见[OMCI 结果码与数据面定位](omci-failure-triage.md)）；
2. carrier 与实际收发（往目标端口发包后看 `tx_dropped`，以及 `fttr0` 上是否出现对应 VLAN/PCP）；
3. 接线与环路（`own address as source address`、异常包速、断开冗余链路后现象是否消失）；
4. 以上三层干净后，按 ONU 队列、业务 GEM、实际 BWmap、主猫接收逐跳取证；再决定
   查实体/指针、授权与帧处理，还是子猫原生 WAN 路径，不能一律回到 OMCI 重建。

固定节律（例如每 15 秒拆 carrier、每 30 秒重配一次）通常是活体判定或门控条件的问题，不是设备"随机不稳定"。把节律与日志指纹一并记录，比反复重启更有价值。

## VLAN 与 ACS 发现

分别记录 ONU ID、内部 GEM/封装标签、业务 VLAN、管理 VLAN、主猫桥接配置；标签数值相似也不能混用。透明 EVTO 表不提供唯一业务 VLAN；一次 DHCP 标签不等于出厂默认 VLAN。

分别记录原生 `ManagementServer.URL`、OMCI 管理关联及 `ConnectionRequestURL`。ME 340 未关联只说明该管理路径状态，不能推出原生 ACS URL 为空。主猫 ACS 监听正常不证明目标客户端可达。

按当前 CLI 帮助读取状态/已知设备；若目标未建会话，不能凭空查询其 CWMP 参数。GetParameterValues/Names 是主动的只读 RPC，需纳入实验范围并核对目标；Set、Add、Delete 和自动 bootstrap 是配置动作。不要为了查地址打印密码参数或批量导出所有参数。

公开资料标注型号、硬件、固件、来源与可信度。论坛用户的地区 VLAN 配置只作线索。恢复出厂会改变调查对象，必须单独说明影响并取得明确指令，不能用来猜默认值。

## 管理网络与 CWMP 的区分诊断

以下方法来自 2026-11-01 的 [SG631Z-C 案例](star-sg631z-c-case.md)，是取证顺序，不是所有设备的固定行为：

1. **先证实管理网络。**交叉核对设备 WAN 页、主猫 DHCP 租约、邻居和当前目标的请求响应。
   ME 134 的 IPOptions/当前地址为零时，先确认实体与实际管理 WAN 的关联；这些字段
   可能不足以反映该设备的管理 WAN 实际状态，不能据此盲写 DHCP/IP 栈开关。
2. **验证抓包覆盖面。**某个 `fttrN` 看不到管理单播时，核对实际管理桥和接口路径。
   在管理桥采样时仍需以当前目标身份/地址过滤；共享 ACS 的流量可能来自其他 ONU。
   记录接口、过滤条件、方向、时间窗口和可控刺激，静默窗口只支持有限结论。
3. **分开记录三种状态。**目标到 ACS 的 TCP/HTTP、真实 Inform/InformResponse、
   控制器光侧/CWMP 身份关联分别取证。若 ACS 已有目标会话而状态仍为 `waiting_inform`，
   核查当前端点、会话来源和身份匹配，不要继续把它解释为没有上报。
4. **身份规则必须有作用域。**光侧串号与 CWMP SerialNumber 可能编码不同或采用复合格式。
   依据当前设备证据限制厂商、型号和完整串号，拒绝多候选，不使用任意子串或部分串号
   自动关联。专属规则放在厂商下的型号模块；关联成功不代表存在业务参数契约。
5. **先验证真实只读 RPC。**会话建立后先做 GetRPCMethods，再按需读取非敏感参数。
   RPC 名称列表不证明写入能力；任务排队不等于失败，按任务状态查询完成结果。
   HTTP 401/Digest 挑战只证明连接请求服务可达，不证明认证成功或已触发 Inform。
6. **配置周期与实际节奏分开。**记录修改前后周期、保存时间与真实会话时间。
   读取到短周期不代表已测得同样节奏；未受控复现时不把厂商负载保护或退避定为根因。
   临时改动按实验约定恢复；用户主动保留的值不能擅自恢复。长周期还需核对 freshness
   判定，避免把预期的安静期误报为离线。

没有常用抓包工具时，可在授权范围使用最小被动探针，只输出协议计数或固定事件标签。
不导出任意 HTTP/SOAP、认证头或原始载荷；先登记接口副作用与资源，完成后清理。
这类探针不能替代目标归属核验，也不能用明文协议标记方法推断加密会话内部内容。

## 有界硬件对照与资源生命周期

方法来自 [TY-FS803G 案例](scty-ty-fs803g-case.md)，不提供跨型号通用的寄存器试写表。

- **先形成可区分预期。**例如“队列出队但主猫未收到”与“没有数据授权”需要不同观测。
  保留基线、候选、恢复三段，以及同窗 OMCI 活体和至少一个健康 ONU 的定向流量。
- **从已知小范围开始。**授权值须验证实际 BWmap 和其他 ONU 共存；一次过大窗口可能
  挤掉 OMCC 并令全链路重配。不得跳过 daemon 硬件所有权检查，或靠永久停用管理授权
  宣布修复。暂停管理窗口时限明确，最后必须恢复并同时验证 OMCI 与业务。
- **恢复也是结果。**写前保存原值/注册代次，回读候选；用 RAII/trap 做异常恢复，并在
  外部再次读回。恢复前比较当前值：只恢复仍等于本轮候选的状态，遇到离线清理或并发
  修改则报告冲突。进程被强杀/掉电时不能保证析构运行，重连先核查而非继续下一实验。
- **不要只读脚本退出码。**厂商工具可能输出有效枚举但返回非零，或打印“成功”却没有
  生效；按已验证输出、运行态回读判断。检查退出路径和恢复函数是否也被 `set -e` 中断。
- **检查完整 lease 路径。**配置成功保留的 Alloc-ID、通道和授权值，不能被下一次临时
  诊断 lease 重置。回归配置失败恢复、成功提交、临时重开、离线清理及槽位复用；策略
  与缓存均需明确 daemon/进程作用域，外部进程不能假定继承进程内所有权。
- **采集不能拖垮恢复。**记录完整 MIB 耗时及锁持有者，区分自动遥测和显式诊断。
  出现重复上传/长时间占锁时先确认调用方，不能为单型号盲目缩短全局超时或去掉锁。

## 出厂基线与原生通信验收

先问清现有 Routed/Bridged、VLAN、端口绑定是否人为改过。修改配置与恢复出厂分别
记录授权及影响；用户自行重置后，重新发现 WAN 实例/接口、身份、注册代次、桥成员
与租约位置，旧脚本的接口编号和写入前提自动失效。不能把某次恢复出厂成功写成所有
设备接入的必要步骤，也不能让适配器静默清空配置。

原生验收依次覆盖 DHCP、地址/路由、双向 ARP、网关与公网 ICMP、DNS/TCP/HTTP，
再由 LAN/Wi-Fi 接入终端测试。临时地址/路由/规则成功只作为定位实验，清理后重新
验证；原生通信、管理网络和 CWMP 分别填结果。原厂日志缺 option125、历史 Root TM
错误、临时 Connected 或进程存在都不能独立充当根因/成功证据。

## 结束条件

交付可复核的分层结果；列出尚缺的最小证据和下一实验。删除自己的远端暂存/探针，恢复本轮临时状态，核对工作区差异；不要覆盖其他人的并发修改。共享输出再次脱敏，且不输出原始账号、报文身份或认证信息。
